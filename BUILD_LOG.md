# Build log

Real failures and design decisions, dated as they happen. This feeds the Loom's "what broke" section, so never add an entry after the fact that didn't happen.

## 2026-11-07
- Project created. The idea grew out of ACPT (solo entry at Summer Up, CODE University, Aug 2026), which was pitched as AI-agent governance and got no letters of intent. Decision: reframe around € at risk per decision.
- Checked against Langdock's public docs/changelog (7 Nov): Agent Evals (test sets), Governance (per-version approval), Guardrails node (in-workflow output checks) exist. Nothing found for after-deployment, per-decision verification against systems of record.
- Stack agreed with Tanatswa: Next.js 16 + React 19 UI (Tanatswa picked Next.js over the plain-HTML option), Zod 4, tsx; no database, no logins. ACPT's `lib/verification/{compare,evaluate,normalize,evidence-resolver,path-resolve}.ts` and `lib/contracts/workflow-verification.ts` copied in unchanged (ACPT commit ed648c0, 13 Aug 2026). The `@/` path alias is kept so the copies stay byte-identical.
- Design decision: each claim becomes an ACPT "expected rule" with a static value, and each looked-up system-of-record row becomes an ACPT "evidence event". ACPT's `passed / failed / insufficient_evidence` maps to `verified / contradicted / unsupported`. So the verdict logic is ACPT's, not new code.
- Design decision: cert expiry and contract end dates are treated as inclusive (`gte`), after writing edge cases #9 (cert expires 2 days after) and #33 (contract ends the same day). With ACPT's `gt` both would have been false "contradicted" flags.
- **Broke:** first offline run flagged 2 decisions labelled "good" (#17 and #51) and showed a split-order message on #22. Cause: the dataset generator picked random suppliers for clean decisions, and twice it put two orders to the same supplier and cost center within 72h, adding up to more than €10,000. These were real policy violations that my pass-1 labels missed. Fix: generator now keeps random clean orders away from each other and from the planted cases. Lesson for the label guide: planted labels alone are not ground truth, so a second independent pass is needed.
- Offline (AI-off) result after the fix: 11 of 15 bad decisions flagged, 0 good decisions flagged. The 4 misses are all free-text-only logs (legacy agent v1.8), where code has no structured fields to check. That is the gap the model is for.

## 2026-11-08
- Fixed the receipt view: for a verified "contract in force" claim it showed `valid_from` instead of `valid_until`, because it displayed the first rule. It now shows the deciding rule (the failing one, or else the last). The ISO messages now spell out the cert ID and how long before the decision it expired; that text is computed by code from the record.
- Price check for cost per decision: the only prices I could find for gpt-4.1-mini / gpt-5-nano / gpt-5-mini came from third-party aggregators, not OpenAI's page. They're stored in `config/prices.json` with that caveat. Costs are reported in $ until a € rate is set.
- Design change (Tanatswa's request): the extractor is no longer tied to an OpenAI key. `lib/receipts/providers.ts` picks the provider from `LLM_PROVIDER`, or from whichever key is in `.env`: OpenAI, Anthropic (native Messages API), Gemini, Mistral, Groq, OpenRouter, Ollama, Langdock or any custom OpenAI-compatible URL. Untested providers are labelled as such until a real run exists. A provider without a JSON mode may wrap its JSON in a ``` fence; only the fence is stripped, and the Zod schema still decides.
- Design change (Tanatswa's request): keys are entered **in the app**. The new Settings page lets you pick a provider and model, paste a key, test it on receipt #14, and run extraction on all 60 decisions. The run and eval logic moved from `scripts/` into `lib/receipts/run.ts` and `lib/receipts/evaluate.ts` so the CLI and the UI share it. The key stays server-side (process env, plus git-ignored `.env.local` only if "Remember" is ticked) and is shown masked. The dev server now binds to 127.0.0.1.
- **Broke:** the first Settings test against an unreachable endpoint showed only "fetch failed", which tells the user nothing. Network errors now name the host and the cause, with a 60 s timeout.
- **Broke:** "forget" removed the key but left `LLM_PROVIDER=custom` set, so the page then showed a "needs LLM_API_KEY" error instead of going back to AI-off. Forgetting the active provider's key now also clears provider, model and base URL.
- Verified in the browser with a dummy key against a dead local port (nothing written to disk): saved, shown as ••••ab12, the full key absent from the page HTML, the test failed with a clear message, "forget" restored AI-off.
- UI/UX redesign (Tanatswa: "fix the UI/UX"). Problems found from screenshots: the header took a quarter of the screen; the agent's "✓ success" and the receipt's "Verified" pills looked identical, which hid the core contrast; on receipt #14 the failed fact sat below the fold in a 6-column table of JSON. Changes: a one-row header with an AI off/on switch; stat cards and status filters on the decision log; each receipt opens with a verdict banner ("1 of 9 facts failed", the finding, € at risk); the agent's note is shown with record IDs coloured by verdict; facts are shown as "Agent said / Record says" rows, problems first; the queue compares this queue vs random vs largest-orders. Wording is generated by `lib/receipts/describe.ts` from the existing verdicts and never changes one.
- Honesty fix found during the redesign: the decision list showed amounts for free-text decisions by guessing the PO number from the receipt number (a generator shortcut). It now shows only a PO the receipt actually knows from the tool call or extracted claims; otherwise "unknown".
- Ingestion question (Tanatswa): "what exactly are we monitoring and how do we pull the data?" Honest answer at the time: nothing was pulled; all data came from generated JSON files. Plan agreed: reuse ACPT's telemetry pattern, where n8n HTTP Request nodes **pushed** `run.started → workflow.step.* → run.completed` to `/api/events` (reference: Tanatswa's exported ACPT AI Invoice Agent workflow).
- Design change: **no n8n.** n8n Cloud costs money, so it's replaced by (a) a built-in tool-calling procurement agent and (b) a replay script. Both post telemetry over HTTP to the same `/api/events` an external agent would use. The endpoint stays n8n-compatible, so free self-hosted n8n could still post to it. Checklist: `docs/BUILD_CHECKLIST.md` (approved 8 Nov).
- Built: ACPT's `lib/contracts/ingest-event.ts` copied unchanged (ACPT 759a874); `POST /api/events` (bearer key, Zod, duplicate check, local JSONL store, same status codes as ACPT); event → decision adapter (`lib/live/adapter.ts`, spec in `docs/TELEMETRY_MAPPING.md`); replay; built-in agent with a documented stale supplier cache (snapshot 15 Jan 2026); Sources panel; File/Live switch; live feed that refreshes itself; run timeline per receipt.
- Measured: the replay of 60 decisions as 180 events gives the same 11 flagged as the offline run. Ingest → receipt latency (round trip of each `run.completed` POST, verdict included): p50 15.3 ms, p95 17.3 ms, max 19.4 ms (n = 60, local). A second replay is fully de-duplicated (9/9 events → 200).

- **Broke (real):** gpt-5-nano produced 2 invalid outputs (D-003, D-029). Both put a `claimed_valid` field on a claim type that doesn't allow it, so the schema rejected the whole output, as designed. D-029 is a free-text-only decision, so with no valid output it stays "unchecked" rather than being guessed verified. D-003 fell back to its tool-call claims.
- gpt-5-nano is a reasoning model: 263k completion tokens for 60 short notes (mostly hidden reasoning), about 11× slower and 3× pricier than gpt-4.1-mini for worse extraction recall. The bigger, older-style model is the better fit for this narrow job. Model choice matters for cost, not for truth: both runs got identical verdicts on the bad decisions, because code sets the verdicts.
- **Honest caveat:** the free-text notes were written by my own generator from a handful of templates, so 100% recall shows the pipeline works end to end. It is not evidence of how well extraction would do on messy real agent logs. A real log sample is the next test.
- **Built-in agent on a real model** (gpt-4.1-mini, 6 pending requests, telemetry via `/api/events`): it approved PO-4601 (SUP-104, cert expired 7 Feb) and PO-4605 (SUP-107, cert expired 10 May) because its stale supplier cache (15 Jan 2026) said "certified". Both receipts were **flagged against the live supplier DB** (€7,560 and €3,200 at risk). It correctly rejected PO-4603 (over budget and over the €10,000 limit); the other 3 verified. 5–7 tool calls per request, about 3 s of model time, 10,548 input + 1,512 output tokens in total (about $0.0011 per request at list price).
- Uniqueness checklist filled with proof (`docs/uniqueness-checklist.md`): 21 ticked, D2 partial (manual label pass outstanding), and B4 / D4 / E3 / E5 open until the Loom is written and recorded. All five "wrapper" red flags are false, with the reason stated for each. Loom script drafted: `docs/LOOM_SCRIPT.md` (~620 words, timed sections, click path, pre-recording checks).
- Final pass on a **clean copy** (no node_modules, no `.env.local`, no live data): `npm ci`, typecheck, 40/40 tests, offline run and `next build` all succeed. So the repo runs from scratch with no secrets.
- **Must fix before any deployment (not needed for the local demo):** `next build` warns that the `.env.local` file access in `lib/live/ingest-key.ts` makes Next trace the whole project into the server output. Deployed, that could ship `.env.local`. Fix by reading the ingest key from the environment only in production. Deployment is out of scope, so it's logged, not changed.
